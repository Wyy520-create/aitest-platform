# mini-mall 注入缺陷设计文档

> 本文件是 aitest-platform 的核心设计之一：被测系统**有意**埋入 5 个真实感缺陷，
> 用于验证测试引擎的真实缺陷发现能力。所有缺陷在代码中均有 `BUG-0x` 标记注释。
>
> 面试叙述：这不是"教程 demo 全绿"，而是"我的测试套件在持续抓真实缺陷"。

## 缺陷总表

| 编号 | 类型 | 位置 | 触发方式 | 预期正确行为 | 抓它的用例类型 |
|------|------|------|---------|-------------|---------------|
| BUG-01 | 水平越权 | GET /api/orders/{id} | 用户B访问用户A的订单id | 403 拒绝 | 安全/越权用例 |
| BUG-02 | 并发超卖 | POST /api/orders | 10 并发抢库存 5 的商品 | 成功订单 ≤ 5 | 并发用例 |
| BUG-03 | 金额精度 | models.py price 用 Float | 0.1 元商品 x3 下单 | total == 0.3 | 边界值用例 |
| BUG-04 | 参数校验缺失 | POST /api/cart | quantity = -5 | 422 拒绝 | 异常参数用例 |
| BUG-05 | 静默分页错误 | GET /api/products?page=0 | page=0 | 400/422 拒绝 | 边界值用例 |

## 逐个说明

### BUG-01 水平越权（高危）
- **现象**：任何登录用户可遍历 order_id 查看他人订单（金额、购买明细）
- **根因**：只做了认证（是谁）没做授权（能不能看这条数据）
- **正确写法**：`if order.user_id != me.id: raise 403`
- **对照**：购物车模块的改/删做了归属校验（正确示范），同项目内两种写法对照
- **危害量化**：脚本遍历 id 可拖库全站订单

### BUG-02 并发超卖（高危）
- **现象**：库存 5 的商品被并发下单卖出 >5 件
- **根因**：`检查库存` 与 `扣减库存` 非原子，读-改-写竞态（丢失更新）
- **正确写法**：`UPDATE ... SET stock = stock - :qty WHERE id=:id AND stock >= :qty` 检查受影响行数；或 SELECT FOR UPDATE 行锁；或乐观锁版本号
- **抓法**：测试用 ThreadPoolExecutor 10 线程同时下单同一商品，断言成功订单数 ≤ 初始库存

### BUG-03 金额精度（中危）
- **现象**：0.1 元 x3 结算出 0.30000000000000004 元
- **根因**：金额用二进制浮点数（Float），无法精确表示十进制小数
- **正确写法**：数据库 Numeric(10,2) + Python Decimal
- **现实案例**：对账系统差一分钱都是事故；累计百万笔订单误差放大

### BUG-04 数量负数（中危）
- **现象**：加购 quantity=-5 成功，下单时总金额为负（平台倒贴钱）、库存反向增加
- **根因**：Pydantic 契约只声明 `int` 没声明 `gt=0`
- **正确写法**：`quantity: int = Field(gt=0, le=999)`
- **连锁反应展示**：单点校验缺失沿业务链放大成资金风险

### BUG-05 静默分页错误（低危但阴险）
- **现象**：page=0 返回 200 且数据与 page=1 相同（负 offset 被静默当 0）
- **根因**：分页参数无下界校验
- **正确写法**：`page: int = Query(ge=1)`
- **为什么阴险**：不崩溃、数据"看起来正常"，错误沿数据流蔓延（报表/缓存/前端翻页全错）

## 缺陷用例的断言策略

抓缺陷的用例一律断言**正确行为**（而非迁就 bug），执行结果失败 = 发现缺陷。
这些用例打上 `@pytest.mark.bug_detection` 标记，报告中单独统计：
`5 failed` 不是测试套件的问题，而是套件正在工作的证据。
