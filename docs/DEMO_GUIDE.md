# 部署演示指南（面试官 / 零基础友好版）

> 本文档回答四个问题：①这个项目是什么、3 分钟怎么讲明白；②从零部署运行需要什么、一步步怎么做（含 Windows）；③面试现场怎么用 cpolar 公网演示；④被问"印象最深的 bug"怎么答。

---

## 0. 这个项目是什么（先花 1 分钟看懂）

**aitest-platform 是一个"自带缺陷的电商系统 + 智能测试平台"的全栈项目**：

- **mini-mall**（被测系统）：一个电商后端 API，故意注入了 7 个真实缺陷（越权、并发超卖、金额精度、边界静默错误等）；
- **测试平台**：对被测系统跑 45 条自动化接口用例，**全部命中那 7 个缺陷**；带 AI 辅助用例生成（生成 → 人工评审门禁 → 入库）、RAG 知识库问答（自实现 BM25 检索 + 拒答保护）、数据仪表盘；
- **工程化**：docker compose 一键起全栈，GitHub Actions 三条 CI 作业 88 秒全绿（接口自动化 / 平台端到端 / RAG 检索质量评测）。

### 3 分钟面试讲法（可直接照着讲）

**第 1 分钟 · 是什么：**
"这是一个智能接口测试平台，但它不是 PPT 项目——它带一个我亲手写的、埋了 7 个缺陷的电商系统 mini-mall，平台对它跑自动化测试，7 个缺陷全部被发现。整体四个部分：被测系统、Pytest 分层测试引擎、Vue3 + FastAPI 的测试平台、AI 模块（用例生成 + RAG 问答），docker compose 一键起全栈，CI 三条作业自动回归。"

**第 2 分钟 · 能做什么（按演示路径）：**
"登录平台后：执行中心一键跑 45 条用例，报告里 7 个 failed 就是被测系统的 7 个真实缺陷，每个失败用例都带缺陷定位说明；AI 工场从被测系统的 OpenAPI 文档自动生成测试用例草稿，但**必须经过人工评审才能入库**——我不信任 AI 的直接产出，这是 AI 治理的落地；RAG 问答可以问项目知识，比如'秒杀为什么超卖'，它检索知识库作答，无关问题会拒答而不是瞎编。"

**第 3 分钟 · 亮点（挑两三个深入）：**
"技术上我印象最深的三点：一是执行层完全数据驱动，用例只存相对路径，被测系统地址是唯一环境变量，换系统只要改一个变量；二是 RAG 的拒答阈值没有拍脑袋——我发现 BM25 绝对分和查询长度正相关，短查询会被误杀，所以用'得分率 = 实际分 / 理论满分'归一化，阈值 0.055 落在实测分离带中间，21 条评测集进了 CI 防回归；三是 AI 生成的用例有采纳率统计，度量 AI 而不只是使用 AI。全部代码和 CI 都在 GitHub 上，clone 下来一条命令就能跑。"

## 1. 部署运行：需要什么 + 怎么做

### 1.1 前置条件（只需要这一个）

| 你的系统 | 需要安装 | 说明 |
|---|---|---|
| Windows 10/11 | Docker Desktop for Windows | 官网下载安装即可，会自动启用 WSL2 |
| macOS | Docker Desktop for Mac | 官网下载安装 |
| Linux | Docker Engine + Docker Compose | `sudo apt install docker.io docker-compose-v2`（Debian/Ubuntu） |

> **就这些。** Python、Node、数据库都不用装——全部在容器里。机器内存建议 4GB 以上。
> 另外需要一个 Git 客户端（克隆仓库用）；Windows 上没有 Git 也可以直接下载 ZIP。

### 1.2 一键部署（macOS / Linux，共 4 条命令）

```bash
# ① 克隆仓库（公开仓库，无需任何凭据）
git clone https://github.com/Wyy520-create/aitest-platform.git
cd aitest-platform

# ② 创建环境配置文件（管理员密码 / LLM key 都在这里，默认即可跑）
cp .env.example .env

# ③ 构建并启动全栈（首次约 2~5 分钟，看网速；之后每次几秒）
docker compose up -d --build

# ④ 等待约 10 秒让后端就绪，然后打开浏览器访问
#    http://localhost:3000
```

**验证成功的标志**：浏览器打开 `http://localhost:3000` 出现登录页 → 输入账号 `admin` 密码 `admin123` → 进入平台看到"看板"页统计图表。

### 1.3 Windows 部署（PowerShell，与上面完全等价）

```powershell
# ① 克隆仓库（开始菜单搜 PowerShell，右键"以管理员身份"不必需）
git clone https://github.com/Wyy520-create/aitest-platform.git
cd aitest-platform

# ② 创建 .env 文件（PowerShell 没有 cp 命令，用 Copy-Item）
Copy-Item .env.example .env

# ③ 启动全栈（首次约 2~5 分钟）
docker compose up -d --build

# ④ 打开浏览器访问 http://localhost:3000
```

**Windows 三个经典坑**：
1. **`.env` 变成了 `.env.txt`**：用记事本编辑保存时，"保存类型"必须选"所有文件"，文件名就是 `.env`。如果平台行为异常（比如改了密码不生效），先检查文件名。
2. **Docker 没启动**：`docker compose` 报错的先打开 Docker Desktop 等左下角状态变绿。
3. **WSL2 未启用**（老版本 Win10）：Docker Desktop 首次启动会提示，按指引点一下就自动配好。

> 没有 Git 的 Windows 面试官：直接浏览器打开
> `https://github.com/Wyy520-create/aitest-platform` → 绿色 Code 按钮 → Download ZIP →
> 解压后进入目录，从第 ② 步继续。

### 1.4 5 分钟体验路线（面试官跟着点一遍就懂项目）

1. **看板**：通过率趋势、模块分布、统计卡片（数据仪表盘）
2. **执行中心 → 点"执行测试"**：等约 10 秒出报告，**7 个 failed 就是被测系统埋的 7 个真实缺陷**；点任意失败行看缺陷定位（如"page=0 应报错却返回 200"）
3. **用例管理**：45 条用例可按模块筛选，点用例看请求构造与断言
4. **AI 工场 → 生成一批用例**：自动从被测系统接口文档生成草稿 → 逐条"采纳/驳回"写理由 → 右上角采纳率变化
5. **RAG 问答**：点快捷问题（2 个回答 + 1 个拒答），手动输入"秒杀为什么超卖"，点"跑质量评测"看 21 条全绿

### 1.5 卡住怎么办（排查表）

| 症状 | 原因与解决 |
|---|---|
| `localhost:3000` 打不开 | 容器没起完：`docker compose ps` 看三个容器是否都 Up；等 10 秒再刷 |
| 页面能开但登录报 500 | 后端还在启动中，等 10 秒；或 `docker compose logs backend` 看报错 |
| 端口被占用（3000/8000/8100） | 改 `docker-compose.yml` 里 `ports:` 映射，如 `"3001:80"`，然后重新 `up -d` |
| `docker compose` 命令不存在 | 老版本 Docker 用 `docker-compose`（中间有连字符） |
| 改了 .env 不生效 | 环境变量是容器启动时注入的，必须 `docker compose up -d --force-recreate backend` |
| 想看内部日志 | `docker compose logs -f backend`（后端）/ `sut`（被测系统） |

### 1.6 常用命令速查

```bash
docker compose ps                     # 查看容器状态
docker compose logs -f backend        # 跟踪后端日志
docker compose down                   # 停止并删除全部容器（数据保留在卷里）
docker compose up -d                  # 再次启动（秒级）
docker compose down -v                # 连数据卷一起删（完全重置，下次启动重新建库）
```

## 2. 面试现场：cpolar 公网演示

适用场景：线上面试共享屏幕 / 面试官想在自己设备上真实点开平台。

### 2.1 步骤（演示前 2 分钟完成）

```bash
# ① 确认平台在跑
docker compose ps        # 三个容器都 Up

# ② 启动 cpolar 隧道（前台运行，演示期间保持这个终端开着）
cpolar http 3000
```

输出示例：
```
Forwarding  http://a1b2c3d4.cpolar.io -> http://localhost:3000
Forwarding  https://a1b2c3d4.cpolar.io -> http://localhost:3000
```

把 `https://a1b2c3d4.cpolar.io` 发给面试官或投屏打开——任何人都能访问你的平台登录页，当场登录操作。**进阶秀法**：自己手机 4G 打开该链接验证，证明是真实公网可访问。

### 2.2 没有装 cpolar？（一分钟装上）

```bash
# Linux
curl -L https://www.cpolar.com/static/downloads/install-release-cpolar.sh | sudo bash

# Windows / macOS：官网 https://www.cpolar.com 下载客户端，双击安装
```

### 2.3 现场话术（cpolar 与公司正式部署的对应）

> "本地演示我用 cpolar 做临时内网穿透，把本机 3000 端口暴露到公网。**正式部署时这套 docker-compose 原样搬到公司服务器**——compose 编排、服务拓扑、CI/CD 全部不变，唯一变化是把临时隧道换成服务器上 nginx 直接监听 80/443，再挂域名和 HTTPS 证书。容器化的意义就在于此：环境一致性不依赖任何特定机器，换一台装了 Docker 的主机，一条 `docker compose up -d` 就上线。"

### 2.4 注意事项

- 免费版隧道**域名每次重启会变**——所以现场生成现场用，不要提前写进简历
- 演示期间电脑**不能睡眠/断网**（系统设置里临时关掉睡眠）
- 演示完 `Ctrl+C` 关闭隧道即可

## 3. 面试弹药：印象最深的三个 bug（STAR 讲法）

被问这个问题时，**讲排障过程比讲 bug 本身值钱**。每个故事按"情境 Situation → 行动 Action → 结果 Result"组织，30~60 秒一个。

### 故事一：推送后 CI 完全没有运行（配置类问题的排障方法论）

- **情境**：代码推上 GitHub 后，Actions 页面空空如也，workflows API 返回 0 条记录——不是失败，是根本没被触发。
- **行动**：按判别顺序排查：先确认 workflow 文件在远端存在（raw URL 能访问）→ 再用知名公开仓（actions/checkout）做**匿名 API 对照实验**，排除"查询方式不对"的误判 → 最后通读配置发现触发条件写的是 `branches: [main]`，而仓库默认分支是 `master`——事件从未匹配，GitHub 根本没注册这个 workflow。
- **结果**：改成 `[master, main]` 推送后 CI 立即激活，三作业 88 秒全绿。教训：**"文件在但行为没发生"时，先看触发条件与真实环境是否匹配**；对照实验能快速隔离"配置错"还是"平台怪"。

> 加分句：这个问题是新手最容易卡的——CI 不报错也不运行，没有任何错误信息可抓，考验的是排障方法而不是工具熟练度。

### 故事二：RAG 把正常问题误判拒答（算法理解 + 数据驱动决策）

- **情境**：知识库问答里"秒杀为什么超卖"被判为"知识库无相关内容"拒答了，但语料明明有对应文档。本地评测集 18 条全过，它却是个漏网之鱼。
- **行动**：先排除语料缺失（容器内文件齐全）→ 写探查脚本跑全部评测用例的分数，发现根因：**BM25 绝对分与查询长度正相关**——拒答类问题最高 4.08 分与正常短查询 2.71~4.11 分完全重叠，任何绝对阈值都会误杀一片 → 于是做归一化：用"得分率 = 实际分 / 该查询理论满分（每个词都命中时的上限）"，跨查询长度可比 → 实测分布出来分离带 [0.046, 0.070]，阈值取中间 0.055。
- **结果**：误拒修复，把这个漏网查询补进评测集第 7 类"口语化短查询"防止回归，评测集扩到 21 条，本地/容器/CI 三端指标完全一致。

> 加分句：我没有拍一个阈值上线，而是先跑数据看分布，让数据决定阈值——测试思维反哺了算法调优。

### 故事三：同一份评测集，容器里分数比本地低（测试环境治理）

- **情境**：同一份代码、同一份评测集，容器里 MRR 0.963，本地 0.972——**评测结果不可比**，CI 断言都没法写。
- **行动**：逐文件比对容器与本地语料，发现 Dockerfile 多拷了一份 README.md 进知识库——README 是导航文档，每个 chunk 都提一遍各模块名，干扰了相关度排序，5 个 chunk 就让 MRR 变了。
- **结果**：确立语料治理规则并写进代码注释：**只有"稳定 + 自包含"的文档才进检索语料**，README 这种变动频繁的导航文档明确排除；修复后三端指标完全一致。教训：评测输入的任何环境差异都会让指标漂移——**先治理测试环境，再谈优化指标**。

### 备用故事：前端表格"表头在、数据空"（实测抓 bug）

- **情境**：浏览器实测发现 AI 工场的草稿表格 ID/用例名/模块三列只有表头没有数据，接口返回明明正常。
- **行动**：用浏览器工具直接抓 DOM，发现"prop 简写列"的表头渲染了但数据单元格缺失，而带 `template` 的列正常——定位为**无构建单文件（in-DOM 模板）下 Element Plus 的兼容差异**，SFC 构建态没这个问题。
- **结果**：全站 11 处统一改显式插槽，坑写进代码注释。教训：**浏览器实测比接口自测多覆盖一层渲染层**，UI  bug 只有真打开页面才现形。
